A base Kaggle calibra taxas reais de conversão, mas não diz como os clientes reagiriam a cada uma das três mensagens. Essas respostas são simuladas, como explicado na seção 3.

Ambiente: Python 3.12 com requirements-lock.txt. As 30 execuções levam alguns minutos.

1. Problema, ações e recompensa¶

O banco precisa escolher como apresentar uma oferta de depósito a prazo já aprovada. As ações são três mensagens: curta, explicação guiada e resumo de benefícios. O contexto é o tipo de contato, conhecido antes da escolha: cellular ou telephone.

A recompensa é 1 quando o cliente converte e 0 quando não converte. Decisões sem resultado informado ficam pendentes na API.

3. Simulador¶

Os primeiros 60% da base calibram uma taxa de conversão por contexto, suavizada com Beta(1,1). Cada mensagem multiplica essa taxa por um fator fixado no config.json antes dos experimentos. O cenário principal tem metade do tráfego em cada contexto. O observed_mix usa a proporção de contatos dos períodos mais recentes, e o equal_arms dá a mesma taxa às três mensagens.

Um piloto de 3.000 escolhas aleatórias serve de ponto de partida para todas as políticas. Depois, cada execução avalia 20.000 decisões novas; as conversões do piloto não entram na conta.

4. Thompson Sampling¶

Cada contexto tem uma distribuição Beta por mensagem, começando em Beta(1,1) e atualizada com o piloto. A cada decisão:

  1. Sorteamos uma taxa de conversão de cada distribuição do contexto.
  2. Escolhemos a mensagem com a maior taxa sorteada.
  3. Observamos o resultado e atualizamos alpha += reward e beta += 1 - reward.

A classe abaixo é a mesma usada no experimento e na API. Referência: A Tutorial on Thompson Sampling, Russo et al..

class ThompsonSampling:
    def __init__(self, seed: int = 42, alpha=None, beta=None):
        self.rng = np.random.default_rng(seed)
        self.alpha = np.ones((2, 3)) if alpha is None else np.array(alpha, dtype=float)
        self.beta = np.ones((2, 3)) if beta is None else np.array(beta, dtype=float)
        if self.alpha.shape != (2, 3) or self.beta.shape != (2, 3):
            raise ValueError("Posterior arrays must have shape (2, 3)")
        if not (np.isfinite(self.alpha).all() and np.isfinite(self.beta).all()):
            raise ValueError("Posterior parameters must be finite")
        if (self.alpha <= 0).any() or (self.beta <= 0).any():
            raise ValueError("Posterior parameters must be positive")

    @property
    def means(self):
        return self.alpha / (self.alpha + self.beta)

    def select(self, context: int) -> int:
        samples = self.rng.beta(self.alpha[context], self.beta[context])
        return int(np.argmax(samples))

    def update(self, context: int, action: int, reward: int):
        if reward not in (0, 1):
            raise ValueError("Reward must be binary")
        self.alpha[context, action] += reward
        self.beta[context, action] += 1 - reward

    def state(self) -> dict:
        return {"alpha": self.alpha.tolist(), "beta": self.beta.tolist()}

Métricas e intervalos¶

Conversão é conversões / decisões, e o ganho é a diferença em pontos percentuais. O arrependimento soma, a cada decisão, quanto se perdeu em relação à melhor mensagem possível. Os intervalos de 95% vêm de bootstrap (5.000 reamostragens) sobre as médias das 30 execuções, usando diferenças pareadas para o ganho.

9. Conclusão¶

O pipeline baixa e prepara a base, compara políticas de forma reproduzível, registra tudo no MLflow e serve recomendações com feedback. O Golden Set cobre os casos de elegibilidade, permissão e contexto desconhecido.

No simulador, escolher a mensagem por contexto converte bem mais que uma mensagem única, e o Thompson Sampling chega perto do máximo possível. A regra fixa por contexto empata com ele num cenário estável. As limitações estão na seção 8 do README.
